Use this when this server cannot reach JIRA (no internet access) while the users' browsers can: the browser runs the search and posts the issues it received back here, where they are mapped, reviewed and imported exactly as in the server-side mode. Nothing else changes; with this unticked the server calls JIRA itself.
JIRA must allow calls from this page (CORS). JIRA Cloud does not send the required headers on *.atlassian.net, so a browser cannot call a Cloud URL directly: put the call behind a proxy that adds the header, or use Atlassian's OAuth gateway (api.atlassian.com, which does allow it). JIRA Server/Data Center can be fronted by a reverse proxy that adds Access-Control-Allow-Origin. Every user is asked for their own JIRA email and API token on the import screen; the credentials stored above are only used in server-side mode. The users can check this with Test connection on the import screen.
